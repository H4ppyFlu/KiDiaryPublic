# React + Vite + TypeScript for the frontend

The PWA is a React single-page app built with Vite and written in TypeScript, served by a FastAPI backend that speaks JSON. The backend is Python with Postgres, all running in containers.

This is deliberately not the simplest choice. Server-rendered Jinja2 templates with a little vanilla JavaScript would build the same three screens with no build step, no second container, and fewer hours spent away from the project's stated learning goals. React was chosen anyway because frontend framework practice is itself a goal, and React is what that practice transfers to; TypeScript for the same reason, since React without it is a dialect most codebases no longer write.

## Consequences

There is a build step, which raises the question of where it runs (see ADR-0007), and a meaningful share of the project's hours will go to UI work rather than to databases, containers, or ML.

The service worker is generated by `vite-plugin-pwa`, with the push subscription and notification-click handling written by hand — the install/manifest/caching boilerplate is not the interesting part, the push logic is.

## Refined when the service worker was actually built (#9)

The paragraph above says the worker is *generated* by `vite-plugin-pwa`. Building it showed that
the plugin's two modes force a choice the sentence did not know it was making, and the mode called
`generateSW` is the one that cannot deliver the rest of the sentence.

`generateSW` writes the whole worker from configuration on every build, so there is no file to
hand-write anything into. Custom code can only arrive through `workbox.importScripts`, pointing at
a file in `public/` that Vite copies verbatim: plain JavaScript, outside `tsc -b`, unbundled, and
unable to import anything from `src/`. The notification-click handling has to build a URL that
opens one Prompt, and it would be doing that in a file that cannot see how the rest of the app
builds URLs.

So the worker is `frontend/src/sw.ts`, and the plugin runs in `injectManifest` mode: it compiles
that file with the rest of the app and substitutes the list of built assets into it. The intent of
the original paragraph stands unchanged — the install, manifest and caching boilerplate is still
the plugin's, and the precache list is still generated — but the worker itself is ours, because
that is where the push logic has to live.
